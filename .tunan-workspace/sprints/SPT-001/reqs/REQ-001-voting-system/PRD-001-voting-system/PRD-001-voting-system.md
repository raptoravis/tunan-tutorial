# PRD-001: 轻量群体决策投票系统

## Background

源自 REQ-001：sponsor 想要为小型群体（朋友 / 同事，单次 < 50 人）提供一个免注册、链接分享即用的轻量投票工具，典型场景「中午吃什么」、「周末去哪玩」。本 PRD 将 REQ-001 的 6 个 Goals 与 5 个 Open Questions 全部决议为可实现规格。

**已采纳的 REQ 级决策**
- 形态：Web 应用 | 身份：匿名 + 分享链接 | 规模：单次 < 50 人
- 规则：单选 + 实时显示 + 可改票 + 截止时间 | 参与者可截止前追加选项

## Personas

- **创建者 (Creator)**：发起一个投票主题，关心是否能快速分享出去、能否随时关、能否看到结果与（可选）明细。一次性低频使用，移动端为主。
- **参与者 (Voter)**：被链接拉进来，关心能否一眼看懂题目、一秒投上、能否改票。移动端为主。

> 明细公开场景下，访问参与链接的非投票人即「旁观者」体验，由 PRD 接受为 Voter 的子状态，不单列 persona（OQ 已对齐 [[REQ-001]]）。

## User Stories（摘要，详细在 STORY 池）

- **US-1** 作为创建者，我想填一个问题 + 2~10 个选项 + 截止时间，拿到「参与链接 + 管理链接」，以便分享给群里。
- **US-2** 作为参与者，我打开参与链接后能看到题目和当前所有选项，点选其中一个完成投票。
- **US-3** 作为参与者，截止前我能改我的票。
- **US-4** 作为参与者，截止前我能追加一个新选项。
- **US-5** 作为创建者或参与者，我能在结果区看到每个选项当前票数、占比、总票数，≤5s 刷新。
- **US-6** 作为创建者，我能通过管理链接提前关闭投票。
- **US-7** 作为创建者，创建时勾选「公开明细」后，结果区显示每个选项下的投票人昵称列表。

## Functional Requirements

- **FR-1 创建投票**
  - FR-1.1 创建表单字段：问题（必填 1-200 字）、候选项 2-10 条（每条 1-100 字）、截止时间（必填）、公开明细勾选（默认关）
  - FR-1.2 截止时间合法范围：现在 +10 分钟 ~ +30 天
  - FR-1.3 创建成功后返回两个 URL：参与链接 `/v/<id>` 与管理链接 `/m/<id>?token=<...>`
  - FR-1.4 候选项**发布后文案不可修改**（避免旧票歧义）；可在截止前删除或新增

- **FR-2 参与投票**
  - FR-2.1 打开参与链接显示题目、所有候选项、当前票数与总人数、剩余时间
  - FR-2.2 参与者可选填昵称（≤20 字，仅用于显示明细，不参与去重）
  - FR-2.3 单选；截止前可改票，最终以最后一次为准
  - FR-2.4 同浏览器/设备视为同一参与者（按 cookie + 服务端 session id 关联）

- **FR-3 追加候选项**
  - FR-3.1 截止前任何参与者可追加新选项（≤100 字）
  - FR-3.2 追加后该选项立即对所有人可见；已投票者可改投到新选项
  - FR-3.3 候选项总数硬上限 30（防滥用）

- **FR-4 结果显示**
  - FR-4.1 每选项显示票数 + 百分比，总票数（基于参与者数，非票数和——单选场景两者相等）
  - FR-4.2 公开明细模式下，每选项展开显示昵称列表（未填昵称显示「匿名 #N」）
  - FR-4.3 页面每 ≤5s 轮询刷新一次结果（截止后停止轮询）

- **FR-5 截止与关闭**
  - FR-5.1 到达截止时间后自动关闭，参与/管理页面变只读
  - FR-5.2 创建者持管理链接可提前关闭；关闭即视同截止
  - FR-5.3 关闭后仍可访问参与链接查看最终结果

## Non-Functional Requirements

- **性能**：参与页首屏 ≤2s（小型部署，< 50 并发）；结果刷新延迟 ≤5s
- **可访问性**：满足 **WCAG AA 关键路径**（看题 → 投票 → 看结果 + 创建表单）：键盘可达、语义化 label、对比度 ≥ 4.5:1
- **移动端**：iPhone SE (375px) 与常见 Android 设备主流程无横向滚动；触控热区 ≥ 44px
- **可观测**：基础 access log + 错误 log；不要求指标系统
- **安全**：管理 token 不可猜（≥128 bit 随机）；参与 URL 不可猜
- **数据**：单机 SQLite；不要求备份/HA

## Risks

- **R-1 弱去重被绕过**：清 cookie / 换浏览器 = 新身份。缓解：接受此泄漏（[[REQ-001]] Non-Goals 已声明），明细公开 + 昵称可作为社交监督
- **R-2 选项滥用**：参与者追加垃圾选项。缓解：30 条硬上限；超出后由创建者通过管理页删除
- **R-3 截止时间错乱**：客户端时区不同。缓解：服务端权威时间，前端展示本地化
- **R-4 管理链接泄漏**：创建者把管理链接错发到群里。缓解：UI 明显警示「请勿分享此链接」；接受此残余风险
- **R-5 高峰轮询打挂**：50 人并发 5s 轮询。缓解：HTTP cache 头 + 服务端去抖；后续可换 SSE，超出 MVP

## Acceptance

- [ ] FR-1 ~ FR-5 全部满足，含 AC 复选框逐条勾上
- [ ] NFR 阈值达标：首屏 ≤2s / 结果刷新 ≤5s / WCAG AA 关键路径 / iPhone SE 视口
- [ ] Creator 流程（创建 → 拿链接 → 分享 → 提前关闭 → 看最终结果）端到端跑通
- [ ] Voter 流程（打开 → 投票 → 改票 → 追加选项 → 看结果）端到端跑通
