# REQ-001 — 轻量群体决策投票系统

## 用户原话

> 我想做一个投票系统：可以投票去哪里旅游 / 中饭吃什么。

## 我理解的意图

为小型群体（朋友 / 同事，单次 < 50 人）提供一个免注册、链接分享即用的轻量投票工具，典型场景是「周末去哪玩」、「中午吃啥」这类即兴决策。

## Goals

- **G-001** 创建一个投票主题，包含问题描述与 ≥2 个候选项
  - [ ] AC-001.1 创建后获得唯一可分享 URL
  - [ ] AC-001.2 创建者可设定截止时间（必填）
  - [ ] AC-001.3 候选项数量上限 ≥ 10
- **G-002** 参与者通过链接进入页面后，无需注册即可投票（单选）
  - [ ] AC-002.1 未截止时可改票，最终以最后一次为准
  - [ ] AC-002.2 截止后页面变只读，仍可看结果
- **G-003** 投票结果实时显示（每选项当前票数 + 总票数 + 百分比）
  - [ ] AC-003.1 任一参与者投票后，其他在场页面应在 ≤5s 内看到更新
- **G-004** 参与者在截止前可临时追加新候选项
  - [ ] AC-004.1 追加的选项立刻对其他参与者可见
  - [ ] AC-004.2 已投票者可改投到新选项
- **G-005** 移动端浏览器体验为一等公民（视口适配 / 触控热区 / 单手可用）
  - [ ] AC-005.1 在 iPhone SE (375px) 与常见 Android 设备上可正常浏览与投票
  - [ ] AC-005.2 主流程（看题 → 投票 → 看结果）无横向滚动
- **G-006** 轻量防刷票：同一浏览器/设备对同一投票视为同一参与者
  - [ ] AC-006.1 同一浏览器多次投票仅记最后一次（按 G-002 改票语义）
  - [ ] AC-006.2 清 cookie / 换设备视为新参与者（接受此泄漏，写入 Non-Goals 的强校验留待后续）

## Constraints

- 形态：**Web 应用**（浏览器访问，分享链接即用）
- 身份模型：**匿名 + 分享链接**（按设备/浏览器弱去重）
- 规模：单次投票参与者 **< 50 人**，可用 SQLite / 单机部署
- 不引入注册/登录体系

## Non-Goals

- 微信小程序 / 原生 App / IM bot 接入
- 注册账号体系、密码找回、个人主页
- 多选投票、排序投票（Ranked Choice）、加权投票
- 截止后揭晓（hidden tally）模式
- 强防刷票（IP / 手机号 / 验证码）
- 历史投票模板 / 复用 / 归档管理

## Scope Boundary

**In scope**
- 创建投票 / 参与投票 / 看实时结果 / 改票 / 追加选项 / 自动截止
- 移动端 web 浏览器适配
- 单机部署（个人或小团队自托管）

**Out of scope**
- 任何形式的账号体系
- 多端原生客户端
- 大规模公开民调、防作弊审计、风控

## Open Questions

每条 ≤3 候选 + 1 ★ 默认 + 自由文本，留到 [[tunan-prd]] 阶段决议。

- **OQ-001** 可访问性（a11y）目标到哪一级？
  - ★ A: 键盘可达 + 语义化 label + 基本对比度（WCAG AA 关键路径）
  - B: 完整 WCAG AA（包括非关键路径）
  - C: 暂不约束，MVP 之后补
- **OQ-002** 群组归属语义：参与者是否填昵称？
  - ★ A: 选填昵称，仅用于显示「谁投了什么」，不参与去重
  - B: 必填昵称，且作为弱身份依据
  - C: 完全匿名，结果仅显示票数
- **OQ-003** 截止时间最短/最长允许范围？
  - ★ A: 最短 10 分钟，最长 30 天
  - B: 最短 1 小时，最长 7 天
  - C: 不约束
- **OQ-004** 创建者是否可手动提前关闭投票？
  - ★ A: 可以，创建者持「管理链接」可关闭
  - B: 不可以，到时间才关
  - C: 可以，但需输入创建时设的密码
- **OQ-005** 是否在结果页显示「谁投了什么」？
  - ★ A: 默认仅显示总票数；可选公开明细（创建时勾选）
  - B: 始终公开明细
  - C: 始终仅显示总票数

## Research Findings

| # | 来源 | 关键发现 | 对本 REQ 影响 |
|---|---|---|---|
| R-1 | Doodle / WhenIsGood / 群接龙等同类产品共识 | 免注册 + 分享链接 + 截止时间是体验底线 | 已纳入 G-001/G-002 |
| R-2 | 同类产品 UX 反馈 | 移动端选项过多时勾选难、误触多 | 已纳入 G-005（移动端一等公民） |
| R-3 | 公开投票安全研究 | 纯前端去重 = 弱防刷；强校验需 IP/手机号 | 弱去重纳入 G-006；强校验入 Non-Goals |
| R-4 | a11y 指南（WAI-ARIA） | 单选/列表组件需正确 role 与键盘交互 | 入 OQ-001，PRD 阶段决议 |
| R-5 | 同类产品坑 | 选项作者改题面后旧票歧义 | 暂入 Open Questions（OQ-006 候选）：建议禁止修改已发布的选项文案 |
