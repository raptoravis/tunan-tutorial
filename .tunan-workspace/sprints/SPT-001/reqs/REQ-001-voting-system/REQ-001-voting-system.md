# REQ-001 — 多场景投票系统

## 用户原话

> 我想做一个投票系统：可以投票去哪里旅游 / 中饭吃什么。

## 我理解的意图

一个轻量的多场景投票系统：用户可以为不同的"决策话题"（如周末去哪旅游、今天午饭吃啥）创建投票，列出候选项，邀请参与者投票，最终基于得票数得出决策。

## Goals

- **G-001 创建投票主题**：用户可以创建一个投票主题，包含标题（如"周末去哪玩"）和若干候选项。
  - [ ] 主题标题非空，长度 ≤ 100 字符
  - [ ] 至少 2 个候选项，每项 ≤ 50 字符
  - [ ] 候选项不允许重复
- **G-002 提交投票**：参与者可以为投票主题中的某一候选项投出一票。
  - [ ] 单次提交只能选一个候选项（单选）
  - [ ] 同一参与者对同一主题不可重复投票（按参与者标识去重，MVP 用昵称或本地 id）
- **G-003 查看结果**：任意时刻可以查看某个主题的当前票数与百分比。
  - [ ] 返回每个候选项的票数与百分比
  - [ ] 按票数倒序排列
- **G-004 列出主题**：用户可以查看所有现存投票主题的列表。
  - [ ] 返回标题、创建时间、当前总票数

## Constraints

- Web 端单页应用（前后端分离）
- 数据持久化使用 SQLite（教学项目，无需高并发）
- 后端 Node + Hono，前端 Vite + React（与 tunan-tutorial 仓库技术栈对齐）

## Non-Goals

- 用户注册 / 登录 / 鉴权（MVP 不做账号系统，用昵称或浏览器本地 id 区分参与者）
- 多轮投票 / 排序投票 / 加权投票（MVP 只做单选）
- 实时推送（结果靠主动刷新或轮询即可）
- 投票截止时间 / 定时关闭
- 邮件邀请 / 分享链接生成（用 URL 直访即可）

## Scope Boundary

**In**：
- 创建主题、添加候选项、投票、查结果、列主题
- 简单 Web UI（创建表单 + 主题列表 + 投票页 + 结果页）
- 本地 SQLite 持久化

**Out**：
- 鉴权、账号、权限
- 多端推送、WebSocket
- 投票审计 / 防刷（MVP 仅按参与者标识去重）
