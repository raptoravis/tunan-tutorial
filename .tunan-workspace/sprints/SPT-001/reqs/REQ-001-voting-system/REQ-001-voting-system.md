# REQ-001 — 轻量投票系统

## 用户原话

> 我想做一个投票系统：可以投票去哪里旅游 / 中饭吃什么。

## 我理解的意图

为小团体（朋友/同事）提供一个能快速创建投票主题、列出候选项、收集每个人选择、并展示结果的轻量系统；典型场景是"周末去哪儿玩"和"今天中午吃什么"——属于低门槛、临时性、低安全要求的决策场景。

## 疑点 / 缺口

集中在 Open Questions 一节，每条都给了 ★ 默认。

## Goals

- **G-001** 用户能创建一个投票主题（含标题 + 2..N 个候选选项）
  - [ ] AC-001a 创建后返回一个可分享的链接 / id
  - [ ] AC-001b 选项数量 ≥ 2、≤ 20
  - [ ] AC-001c 标题非空、≤ 100 字符
- **G-002** 用户能在某个投票主题下提交自己的一票
  - [ ] AC-002a 单选模式（默认）：每人只能选一个选项
  - [ ] AC-002b 已投过的人再次提交 → 覆盖之前的选择（不是追加）
  - [ ] AC-002c 投票需要一个轻量身份标识（昵称即可，无需密码）
- **G-003** 用户能查看某个投票的实时结果
  - [ ] AC-003a 展示每个选项的票数和占比
  - [ ] AC-003b 投票后立即看到自己投了哪个
  - [ ] AC-003c 结果页可被分享访问（不需要登录）
- **G-004** 系统能并存多个投票主题，互不干扰
  - [ ] AC-004a 不同投票 id 之间数据完全隔离
  - [ ] AC-004b 投票主题列表页能看到当前活跃主题

## Constraints

- 单机部署即可，不要求高并发
- 不引入外部账号系统（OAuth / 邮箱注册都不要）
- 数据持久化即可，无需高可用 / 多副本

## Non-Goals

- 不做匿名投票（昵称即身份）
- 不做加权投票 / 多选投票 / 排序投票（首版只做单选）
- 不做投票时间窗口控制（截止时间）—— 留作后续
- 不做权限管理（任何人拿到链接都能投 / 看结果）
- 不做反作弊（同昵称二次投是"覆盖"，不防同人换昵称刷票）

## Scope Boundary

**In：**
- 创建投票（标题 + 选项）
- 提交投票（昵称 + 选项）
- 查看结果（票数 / 占比）
- 多投票并存

**Out：**
- 用户账号体系
- 投票截止时间 / 自动归档
- 多选 / 排序 / 加权
- 管理员后台 / 投票删除 / 选项追加
- 移动端 native app（Web 即可）
