# REQ-001 — 轻量投票系统

## 用户原话

> 我想做一个投票系统：可以投票去哪里旅游 / 中饭吃什么。

## 意图（一句话）

为一群人（朋友 / 同事 / 小团队）提供一个轻量级 Web 投票工具，针对开放性议题（出游目的地、午餐选项等）发起投票、收集多选意见、实时看到结果。

## Goals

- **G-001** 发起人可在 Web 上创建一次投票，包含标题、若干预设候选项、是否允许参与者追加候选项的开关。
  - [ ] 创建投票需输入标题（≥1 字符）且至少 2 个预设候选项
  - [ ] 创建成功后系统返回一个唯一的房间链接（含房间 id 或口令）
  - [ ] 发起人可在创建时勾选「允许追加候选项」

- **G-002** 参与者凭房间链接 / 口令匿名进入投票页，无需注册账号。
  - [ ] 已知房间链接即可进入；非法 / 不存在的房间返回明确错误
  - [ ] 参与者无需登录、不收集邮箱或手机
  - [ ] 同一浏览器会话视作同一参与者（用本地 token 防同一人重复投票）

- **G-003** 投票规则为多选；参与者可勾选 1..N 个候选项后提交。
  - [ ] 至少选 1 项才能提交
  - [ ] 提交后可在截止前修改自己的选择（覆盖式更新）

- **G-004** 当房间开启「允许追加」时，参与者可在投票期间追加新候选项。
  - [ ] 新增的候选项立即对全体参与者可见
  - [ ] 关闭开关时追加入口隐藏，已有候选项不变

- **G-005** 投票结果实时可见：每个候选项当前票数、参与人数、参与者所选项。
  - [ ] 投票后页面立即显示更新后的票数（轮询或长连接，由 PRD 决定）
  - [ ] 票数变化无需手动刷新

- **G-006** 投票数据持久化在 SQLite 中，进程重启后房间、候选项、投票均不丢失。
  - [ ] 房间、候选项、投票三类实体落盘
  - [ ] 重启服务后通过原链接仍可访问同一房间

## Constraints

- 部署目标：单机即可启动（教学/小型场景），SQLite 文件落本地
- 不要求高并发：同一房间预期参与者 ≤ 50 人
- 中文 UI 优先

## Non-Goals

- 用户账号体系、找回密码、个人投票历史
- 跨房间的「我参与过的所有投票」聚合视图
- 排序投票 / 加权投票 / 单选模式（本期只做多选）
- 移动端原生 App、小程序、聊天机器人
- 防机器人 / 防恶意刷票的强校验（仅靠浏览器 token 软防）

## Scope Boundary

**In**：Web 端发起 / 参与 / 实时看结果；匿名 + 房间链接；多选；SQLite 持久化；可选「允许追加候选项」。

**Out**：账号系统；多种投票规则；移动 App / 聊天机器人；强反作弊；管理后台 / 数据导出（留给后续 REQ）。

## Open Questions

留给 PRD 阶段继续收敛，不阻塞本 REQ 入池：

- **OQ-1** 实时同步用轮询还是 SSE / WebSocket？★ 默认轮询（最简单），PRD 阶段决定。
- **OQ-2** 是否需要「截止时间」字段？★ 默认本期不做（房间永久开放，发起人手动关闭）。
- **OQ-3** 发起人是否需要管理权限（删除候选项、关闭投票）？★ 默认需要，凭创建时返回的「管理 token」鉴权。
- **OQ-4** 技术栈选型？★ 默认前后端一体（如 Flask/FastAPI + 简单模板 或 Next.js + SQLite），由 PRD/PLAN 决定。
- **OQ-5** 是否需要二维码方便手机扫码进入？★ 默认 nice-to-have，PRD 评估。

## Research Findings

本期未启用外部 research（教学项目，sponsor 未要求；`research_done: false`）。

凭常识列出可能的坑（供 PRD 参考，不进 acceptance）：

- 类似产品（Doodle、StrawPoll、腾讯问卷）的常见痛点：填问卷不知道别人填了什么 → 本 REQ 选「实时可见」规避
- 匿名投票常见作弊路径：清浏览器数据再投 → 本期接受软防（浏览器 token），列入 Non-Goals 不做强校验
- 多选投票 UX：用复选框 + 即时计数比"勾完一次性提交"更直观，可在 PRD 评估
